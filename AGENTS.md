RankMyMatch technical decisions:
- Consolidate round-time reminders in one secret-verified scheduled route with São Paulo timestamps, per-user delivery claims and existing push preferences; track retries and suppress pending-result reminders after authenticated visits to prevent duplicate or stale prompts.
- Reuse LandingPage for every public entry screen, including login, and display real supplied screenshots in a CSS device frame; this maintains one visual standard without inventing an interface or mutating real rankings.
- Enforce the single supported theme in the root pre-hydration script and shared theme resolver, and remove theme-switch controls; this prevents legacy stored preferences or OS appearance from reintroducing unsupported surfaces.
- Recompute ranking eligibility and positions in database triggers when snapshots, matches, sets, participants, rounds, or season percentage change; this keeps score-edit paths and ranking screens consistent.
- Ranking eligibility requires a player's recorded sets in completed ranking matches to reach max(1, floor(total recorded ranking sets × seasons.min_eligibility_pct / 100)); incomplete or tied sets still count as participation.
- Dispatch single-match result alerts from authenticated finalization and batch alerts only after all batch scores save, so each involved player gets one alert with their saved results and the round destination.
- Format result alerts with one participant list and sequential set scores, and use a transparent monochrome notification badge; this avoids repeated names and Android's square status icon.
- Render shareable round and ranking images in the browser from dedicated offscreen views; this preserves the displayed scores and opens native sharing without saving a screenshot first.
- Default the Home Elo panel to the latest played group's season and order its rating events by round date and match number; replayed Elo events can share timestamps, and the synthetic Geral ranking has no single-group history.
- Record visits through a validated server function rather than open database writes, so anonymous traffic remains measurable without exposing direct insertion.
- Scope profile reads to the owner and shared-group participants, and group-image uploads to members' group folders, so personal data and file writes stay tied to membership.
- Return public bug-vote totals through an aggregate server function while exposing individual vote rows only to their owner, so counts remain visible without revealing voters.
- Keep changelog entries in release_notes with evidence-backed dates and increasing versions (up to six entries per minor); mirror the latest published version in APP_VERSION so displayed releases stay consistent.- Open RoundQuickDialog (wrapping RoundExpandedDetails) for every round/result entry point instead of screen-specific score forms, so presence, draw, match order, sets and tie-break behave identically everywhere.
- Guard async load hooks like useGroupDetail with a sequence counter so a stale run started before auth resolves can never overwrite newer results; otherwise membership/admin state flaps intermittently.
- On batch score save failure, keep the typed scores in place (skip the reload) and show a long error toast, so admins can retry without re-entering results.
- Route hot read-only queries through sharedFetch (src/lib/shared-fetch.ts) with a short TTL so simultaneous hook instances (Home, BottomNav, DesktopNav, popovers) share one request; invalidate the key after mutations that change the data.
- Keep standalone PWA startup in the root shell using the manifest icon and an indeterminate progress bar; dismiss on auth/router readiness without a minimum delay, since native OS startup cannot run custom UI.
- Process account deletions only through the token-verified /api/public/hooks/process-deletions route: claim one request at a time (SKIP LOCKED), record finished steps, and mark "executed" only after the login identity is confirmed gone, so failures stay retryable and never look complete.
- Keep personal profile fields (birth date, Instagram, play preferences) out of client column grants and read them only via get_profile_personal, so privacy settings are enforced by the backend rather than the UI.
- Load GA4/Google Ads only after explicit consent via src/lib/privacy-consent.ts (localStorage + privacy_consents table, notice-versioned); analytics.ts sanitizes paths (no query string, masked invite codes) and keeps ad personalization signals disabled, so tracking never starts before choice and never leaks tokens or invite codes.
- Accept only internal "/" URLs in push payloads and rate-limit senders through push_send_log (30 batches/hour), so notifications can't open external sites or flood group peers.
- Keep the bug-screenshots bucket private with owner-folder/admin read policies; the admin triage renders stored public URLs by extracting the path and creating signed URLs, so legacy rows keep working without public access.
- On consent revocation, stop tracking immediately without reload: analytics.ts gates every event on hasTrackingConsent(), sets the official GA4 opt-out key (ga-disable-<id>), updates consent mode to denied, and deletes _ga/_ga_*/_gcl cookies; ensureGtagLoaded clears the opt-out on re-acceptance.
- Scrub custom analytics event params in analytics.ts (drop keys matching token/invite/code/email/name/auth/session and strings >100 chars) as defense in depth; emitters send only internal IDs and enums.
- Purge operational push logs (push_send_log, round_presence_push_log, admin_pending_reminder_log) and diagnostic logs (whatsapp_logs) after 90 days via the log-retention-cleanup-daily cron job; account deletion records, security audit logs, and transactional email logs are excluded pending an owner-approved retention proposal.
